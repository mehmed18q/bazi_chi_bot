# ربات بازی‌چی تلگرام

یک ربات بازی خصوصی و گروهی برای «گل یا پوچ»، «دوز سه‌تایی»، «سنگ، کاغذ، قیچی»، «حدس کلمه»، «فکر بکر» و
«جرئت یا حقیقت»، ساخته‌شده با Python 3.14، aiogram 3 و SQLite.

در «حدس کلمه»، یک بازیکن کلمه‌ای ۲ تا ۲۰ حرفی انتخاب می‌کند و نفر مقابل به تعداد
حروف آن فرصت حدس دارد. بعد از هر حدس، حرف درست در جای درست با 🟩، حرف موجود در
جای نادرست با 🟨 و حرف ناموجود با ⬛ نمایش داده می‌شود؛ تعداد فرصت‌های باقی‌مانده
هم برای هر دو بازیکن به‌روز می‌شود. نقش‌ها پس از هر دور جابه‌جا می‌شوند.

در «فکر بکر»، کد چهاررنگ از آبی، زرد، مشکی، سفید، قرمز و سبز ساخته می‌شود؛ رنگ تکراری
مجاز است و حدس‌زننده در هر دور ۸ تلاش دارد. مهرهٔ سیاه جای درست و رنگ درست و مهرهٔ سفید
رنگ درست در جای اشتباه را نشان می‌دهد.

در «سنگ، کاغذ، قیچی» هر نفر حرکتش را مخفی ثبت می‌کند و پس از انتخاب هر دو نفر، نتیجه
نمایش داده می‌شود. دست مساوی هم از تعداد دست‌های مسابقه کم می‌کند. این بازی در حالت
دونفره، تک‌نفره با ربات، بازی شانسی و چالش روزانه در دسترس است.

- شمارش‌معکوس خصوصی و ماندگار برای کاربران قبلی ربات، با فاصله‌های ارسال تطبیقی

## راه‌اندازی

Python 3.14 لازم است.

```bash
python3.14 -m venv .venv
.venv/bin/pip install -e '.[test,outreach]'
cp .env.example .env
# BOT_TOKEN را در .env قرار دهید
.venv/bin/bazi_chi_bot
```

اجرای مستقیم از پوشهٔ پروژه نیز ممکن است:

```bash
PYTHONPATH=src .venv/bin/python main.py
```

در BotFather، حالت inline لازم نیست. برای افزودن ربات به گروه، گزینهٔ `/setjoingroups` را فعال کنید. در گروه دستور `/play` مسابقهٔ چندنفره می‌سازد. برای پاسخ‌دادن به نام «بازی چی» در پیام‌های عادی گروه، Privacy Mode را با `/setprivacy` غیرفعال کنید و ربات را دوباره به گروه اضافه کنید؛ با Privacy Mode فعال، ربات معمولاً پیام‌های عادی گروه را دریافت نمی‌کند. بازی‌های خصوصی و لینک دعوت `https://t.me/<bot>?start=join_<token>` همچنان کار می‌کنند.

در مسابقهٔ گروهی، بازیکن‌ها پیش از شروع در خصوصی ربات ثبت‌نام می‌کنند و اشتراک ویژه دارند. سنگ، کاغذ، قیچی با انتخاب مخفی همه، گل یا پوچ با پنهان‌کنندهٔ چرخشی، دوز با جفت‌های چرخشی، حدس کلمه و فکر بکر با سازندهٔ چرخشی، و جرئت یا حقیقت با پاسخ‌دهندهٔ چرخشی و رأی گروه اجرا می‌شوند. کلمه، کد و حدس‌های مربوط در خصوصی با `/gword` و `/gcode` فرستاده می‌شوند؛ کارت گروه فقط پیشرفت و امتیاز را نشان می‌دهد. امتیازهای این مسابقه در جدول همان مسابقه ثبت می‌شوند.

### اتصال با proxy

اگر سروری که ربات روی آن اجرا می‌شود به Telegram Bot API دسترسی مستقیم ندارد،
پراکسی‌ها را به‌ترتیب اولویت در یک آرایهٔ JSON داخل `.env` قرار دهید:

```env
TELEGRAM_PROXY_URLS='["socks5://127.0.0.1:1080", "http://127.0.0.1:7890"]'
```

برای افزودن پراکسی جدید فقط یک رشتهٔ دیگر به آرایه اضافه کنید. ربات آدرس‌ها را به‌ترتیب
تست می‌کند و اولین اتصال سالم را به کار می‌گیرد. اگر هیچ‌کدام در دسترس نباشند، هر ۱۰
دقیقه همهٔ آن‌ها دوباره تست می‌شوند. اتصال فعال نیز هر ۱۰ دقیقه بررسی می‌شود؛ اگر قطع
شده باشد، session و polling از نو ساخته می‌شوند و چرخهٔ تست همهٔ پراکسی‌ها تکرار می‌شود.

آدرس‌های `socks5://...` و `http://...` پشتیبانی می‌شوند. لینک‌های subscription مثل
V2Ray/Clash/sing-box را مستقیم داخل این آرایه نگذارید؛ ابتدا لینک را در کلاینت proxy
وارد کنید تا یک خروجی محلی مثل `127.0.0.1:1080` یا `127.0.0.1:7890` بسازد، بعد همان
آدرس محلی را اینجا تنظیم کنید. اگر آرایه خالی باشد، اتصال مستقیم استفاده می‌شود.

## انتقال یک‌طرفهٔ دیتابیس

دیتابیس زندهٔ سرور باید بیرون از پوشهٔ Git باشد؛ برای نمونه مقدار
`DATABASE_PATH=/var/lib/bazi_chi_bot/bazi_chi_bot.sqlite3` را در `.env` سرور بگذارید.
روش جابه‌جایی اولیهٔ دیتابیس فعلی، پیش از دریافت نسخهٔ جدید، در
[راهنمای استقرار](DEPLOYMENT.md) آمده است. فایل SQLite در شاخهٔ `master` نگهداری
نمی‌شود.

هر بار که `scripts/deploy.sh` با موفقیت ربات را بالا بیاورد، یک snapshot تازه از
دیتابیس سرور می‌گیرد و آن را در Git منتشر می‌کند. برای انتشار دستی یا تلاش دوباره
پس از خطای Git، روی سرور اجرا کنید:

```bash
bash scripts/publish_server_data.sh
```

برای دریافت آن **از Git به لوکال**، روی سیستم خودتان اجرا کنید:

```bash
.venv/bin/python scripts/server_data.py fetch
```

نسخهٔ دریافتی در `data/server_snapshot.sqlite3` ذخیره می‌شود؛ دیتابیس فعال لوکال
جایگزین نمی‌شود. شاخهٔ جداگانهٔ `server-data` فقط توسط فرمان سرور ساخته و به‌روز
می‌شود؛ فرمان لوکال فقط آن را می‌خواند و شاخهٔ کد را تغییر نمی‌دهد. دیتابیس دعوت
`invitation/phones.sqlite3` در این انتقال نیست. چون نسخه‌های SQLite در Git باقی
می‌مانند و حاوی اطلاعات کاربران‌اند، مخزن راه‌دور باید خصوصی و دسترسی به آن محدود باشد.
برای تضمین فنیِ اینکه هیچ کلاینت لوکالی نتواند شاخهٔ `server-data` را push کند،
روی Git server نیز مجوز نوشتن این شاخه را فقط به حساب سرور بدهید.

## دسترسی رایگان و اشتراک ویژه

با اجرای `/start`، کاربر بدون پرداخت به پنج بازی تک‌نفره با ربات، چالش روزانه و
یادآور آن دسترسی دارد. برای بازی دونفره، تورنومنت و مسابقهٔ گروهی باید اشتراک ویژه
داشته باشد. اشتراک ویژه تاریخ انقضا ندارد و فعال‌سازی‌های تأییدشدهٔ قبلی نیز همان
اشتراک محسوب می‌شوند. دکمهٔ «اشتراک ویژه» در منوی اصلی، جزئیات پرداخت را نشان می‌دهد.

### دعوت دوستان

هر کاربر از «دعوت دوستان» لینک اختصاصی خود را می‌گیرد. ورود یک کاربر از آن لینک،
لینک دعوت بازی دونفره یا لینک گروه تنها یک‌بار به یک دعوت‌کننده نسبت داده می‌شود و
۱ امتیاز به او می‌دهد. پس از فعال‌شدن اشتراک دعوت‌شونده، ۱ امتیاز دیگر ثبت می‌شود.
دعوت خود، دعوت تکراری و دعوتِ حسابی که از قبل اشتراک فعال دارد شمرده نمی‌شود.
با رسیدن تعداد دعوت‌شونده‌های فعال به حد نصاب پیش‌فرض ۱۰، اشتراک دعوت‌کننده
خودکار و بدون انقضا فعال می‌شود. فعال‌شدن از راه دعوت نیز می‌تواند دعوت‌کنندهٔ
بالادستی را یک گام به حد نصاب نزدیک کند. ادمین حد نصاب را از «مدیریت ربات ←
تنظیمات دعوت» تغییر می‌دهد؛ کاهش آن، کاربران واجد شرایط را همان لحظه فعال می‌کند.
ربات در ورود بعدی دعوت‌کننده، علت هر امتیاز و تعداد دعوت‌های باقی‌مانده را نشان می‌دهد.

افزودن ربات به گروه فقط برای مشترک ویژه مجاز است. لینک ورود اعضا در پیام ورود
ربات به گروه به افزودن‌کننده نسبت داده می‌شود؛ لینک مسابقهٔ گروهی و دکمهٔ «حاضرم!»
به شروع‌کنندهٔ همان مسابقه نسبت داده می‌شوند.

هر کاربر هنگام ثبت‌نام یک شناسهٔ داخلی ترتیبی می‌گیرد. مبلغ قابل واریز برابر مبلغ
پایه به‌علاوهٔ این شناسه است؛ برای نمونه با مبلغ پایهٔ `100000`، مبلغ کاربر شمارهٔ
`12` برابر `100012` تومان می‌شود. مقدارهای پیش‌فرض:

- مبلغ پایه: `100000` تومان
- شماره کارت: `6219861814466156`
- صاحب کارت: محمد صادق کیومرثی

ادمین از «مدیریت ربات ← تنظیمات پرداخت» می‌تواند هر سه مقدار را بدون راه‌اندازی
مجدد تغییر دهد. کاربر تا پیش از تأیید رسید از بخش رایگان استفاده می‌کند. رسید
متنی یا تصویری عیناً برای ادمین‌های پرداخت ارسال می‌شود و پس از تأیید، وضعیت فعال‌سازی
و مشخصات بررسی در دیتابیس می‌ماند. مبلغ اختصاصی تطبیق پرداخت را ساده‌تر می‌کند؛
اعتبار خود رسید همچنان باید توسط ادمین بررسی شود.

اگر کاربر از لینک دعوت وارد شود و هنوز فعال نباشد، دعوت تا پایان پرداخت ذخیره می‌شود
و پس از فعال‌سازی با اجرای دوبارهٔ `/start` ادامه پیدا می‌کند.

ادمین همچنین در «مدیریت ربات ← کاربران ربات ← پروندهٔ کاربر» می‌تواند هر کاربر را
مستقیماً فعال یا غیرفعال کند؛ تغییر دسترسی بلافاصله ذخیره و به کاربر اطلاع داده می‌شود.

از زمان ثبت‌نام، ربات نام فعلی حساب تلگرام را به‌عنوان نام نمایشی پیشنهاد می‌دهد.
کاربر از گزینهٔ «نام نمایشی» در منوی اصلی می‌تواند نامی بین ۱ تا ۴۰ کاراکتر انتخاب
کند، بعداً آن را تغییر دهد یا دوباره به نام حساب تلگرام برگردد. نام اختصاصی با اجرای
`/start` یا تغییر مشخصات تلگرام بازنویسی نمی‌شود؛ تا قبل از شخصی‌سازی، نام نمایشی
همراه نام تلگرام به‌روز می‌شود.

## شمارش‌معکوس خودکار

مخاطب باید قبلاً ربات را استارت کرده باشد. ابتدا شناسهٔ عددی تلگرام مدیر را در
`ADMIN_TELEGRAM_IDS` قرار دهید و ربات را دوباره اجرا کنید. مدیر می‌تواند مخاطب را با
نام کاربری یا شناسهٔ عددی انتخاب کند؛ تاریخ ورودی میلادی و در منطقهٔ زمانی تنظیم‌شده است:

```text
/countdown @username 2026-09-08 21:30
/countdowns
/cancelcountdown @username
```

مدیر ابتدا از دکمهٔ «⚙️ مدیریت ربات» وارد منوی مدیریت می‌شود و سپس می‌تواند از
دکمهٔ «💌 شمارش‌معکوس»، مخاطب را از فهرست کاربران ثبت‌شده انتخاب کند و تاریخ و ساعت
را مرحله‌به‌مرحله وارد کند. کاربران عادی گزینه‌های مدیریتی را در منوی خود نمی‌بینند.

پیام اول بلافاصله فرستاده می‌شود. سپس تا یک ساعت مانده، هر ساعت؛ از یک ساعت تا ده
دقیقه، هر ده دقیقه؛ از ده دقیقه تا یک دقیقه، هر پنج دقیقه؛ و در دقیقهٔ آخر هر ده ثانیه
پیام ارسال می‌شود. زمان‌بندی در SQLite ذخیره شده و بعد از راه‌اندازی مجدد ادامه پیدا می‌کند.
در هر بار راه‌اندازی ربات نیز برای همهٔ شمارش‌معکوس‌های فعال یک پیام فوری فرستاده می‌شود.

## دعوت کاربران رضایت‌داده

ابزار مستقل `invitation/send_opt_in_invitations.py` شماره‌های فایل
`phones/all_phones.xlsx` را یک بار به دیتابیس مستقل `invitation/phones.sqlite3` وارد می‌کند.
این دیتابیس جدا از `data/bazi_chi_bot.sqlite3` ربات است. جدول `phones` ستون‌های
`id`, `name`, `phone`, `source`, `status`, `is_send` دارد؛ شماره و نتیجهٔ ارسال در یک ردیف
هستند. شماره‌ها به قالب `09xxxxxxxxx` یکسان می‌شوند؛ شماره‌های `9xxxxxxxxx`،
`+989xxxxxxxxx` و `00989xxxxxxxxx` هم به همین قالب تبدیل می‌شوند. ردیف‌هایی که پس از
پاک‌سازی شمارهٔ موبایل ۱۱ رقمی ندارند حذف می‌شوند.
برای شیتی که ستون `source` ندارد، نام شیت به‌عنوان سورس ثبت می‌شود. فایل اکسل بعد از
ورود داده دیگر در زمان ارسال خوانده نمی‌شود.

```bash
.venv/bin/pip install -e '.[outreach]'
.venv/bin/python invitation/send_opt_in_invitations.py --import-excel
```

برای پاک‌سازی دیتابیس موجود بدون ورود دوبارهٔ اکسل:

```bash
.venv/bin/python invitation/send_opt_in_invitations.py --normalize-phones
```

هر دو دستور در پایان، تعداد ردیف‌های باقی‌ماندهٔ هر سورس را چاپ می‌کنند. ورود مجدد به
جدول پُر متوقف می‌شود تا وضعیت‌های ثبت‌شده از بین نروند. برای اتصال اکانت
تلگرام، `TELEGRAM_API_ID` و `TELEGRAM_API_HASH` و در صورت نیاز `OUTREACH_PHONE` را تنظیم
کنید. لینک دعوت را با `OUTREACH_BOT_LINK` یا `--bot-link` تعیین کنید.

پیش‌نمایش بدون اتصال به تلگرام:

```bash
.venv/bin/python invitation/send_opt_in_invitations.py --source test --count 1 --dry-run
```

ارسال واقعی برای یک سورس و تعداد مشخصی ردیفِ در انتظار:

```bash
.venv/bin/python invitation/send_opt_in_invitations.py --source test --count 1
.venv/bin/python invitation/send_opt_in_invitations.py --source vendor_user --count 20
```

`--count` تعداد ردیف‌هایی است که در این اجرا بررسی می‌شوند. پس از هر بررسی، `status`
در همان ردیف به‌روز می‌شود؛ `is_send=1` فقط برای ارسال موفق است. وضعیت‌های نهایی در
اجرای بعدی تکرار نمی‌شوند و خطاهای موقت قابل تلاش دوباره‌اند. وضعیت `SENDING` پس از
وقفهٔ ناگهانی خودکار تکرار نمی‌شود تا پیام احتمالی دوباره ارسال نشود؛ آن ردیف را پس از
بررسی دستی تعیین تکلیف کنید. سقف پیش‌فرض ۲۰ ارسال موفق در روز و فاصلهٔ پیش‌فرض ۱۲۰ ثانیه
است. روی `FloodWait` یا محدودیت اسپم، اجرا متوقف می‌شود.

برای دیدن وضعیت‌ها و شمارهٔ تست:

```sql
SELECT source, status, COUNT(*) FROM phones GROUP BY source, status;
SELECT source, COUNT(*) FROM phones GROUP BY source ORDER BY source;
SELECT id, name, phone, source, status, is_send FROM phones WHERE source = 'test';
UPDATE phones SET status = 'UNSUBSCRIBED', is_send = 0 WHERE phone = '09217074647';
```

## تست

### بانک حقیقت و جرأت

برای پاک‌کردن سابقهٔ بازی‌ها و نگه‌داشتن کاربران و بانک سؤال:

```bash
.venv/bin/python -m bazi_chi_bot.reset_database
```

این فرمان قبل از حذف پشتیبان می‌گیرد، بازی‌ها، پاسخ‌ها، امتیازها، دعوت‌های منتظر و شمارش‌معکوس‌ها
را پاک می‌کند و آمار کاربران را صفر می‌کند. کاربران، وضعیت فعال‌سازی، تنظیمات و
رسیدهای پرداخت و بانک `questions` دست‌نخورده می‌مانند.

فهرست پایه در `content/questions.fa.json` شامل ۱۵۸ حقیقت و ۲۹ جرئت است. کاتالوگ
`content/questions.batch-20260926.fa.json` نیز ۲۵۰ حقیقت و ۲۵۰ جرئت تازه و بدون
هم‌پوشانی با فهرست پایه دارد. پس از ورود هر دو کاتالوگ، بانک شامل ۴۰۸ حقیقت و
۲۷۹ جرئت است. برای ورود به دیتابیس تنظیم‌شده در `.env`:

```bash
.venv/bin/python -m bazi_chi_bot.import_questions content/questions.fa.json
.venv/bin/python -m bazi_chi_bot.import_questions content/questions.batch-20260926.fa.json
```

این فرمان قبل از تغییر، پشتیبان SQLite می‌گیرد؛ ورود مجدد متن یکسان، شناسه و سابقهٔ
قبلی را حفظ می‌کند. متن‌های این فهرست برای انتخاب عمومی فعال می‌شوند.

جدول `questions` شامل `id`، نوع `kind` (`truth` یا `dare`)، متن سادهٔ `text` و
وضعیت `active` است. بانک اولیه خالی است؛ سؤال‌ها بعداً با
`await service.add_question("truth", "متن سؤال")` یا نوع `dare` وارد می‌شوند.
ورود مجدد همان متن و نوع، شناسهٔ جدید نمی‌سازد. برای کنارگذاشتن یک سؤال،
`active` را صفر کنید تا تاریخچهٔ آن محفوظ بماند.

جدول `question_answers` سؤال انتخاب‌شده، نسخهٔ متن هنگام انتخاب، بازی، پاسخ‌دهنده،
هم‌بازی، پاسخ و زمان طرح/پاسخ را نگه می‌دارد. محدودیت یکتای
`(question_id, respondent_id, opponent_id)` از تکرار در تمام مسابقه‌های هر دو نوع
بازی جلوگیری می‌کند. جابه‌جایی پاسخ‌دهنده و هم‌بازی یا عوض‌شدن هم‌بازی، مجاز است.
سؤال از لحظهٔ انتخاب رزرو می‌شود، حتی اگر هنوز پاسخی ارسال نشده باشد.
وقتی سؤال تازه‌ای موجود نباشد، برنده سؤال/چالش را می‌نویسد. سؤال دستی هم با نوع
انتخاب‌شده و `active = 0` ذخیره می‌شود تا وارد انتخاب عمومی نشود؛ همان قاعدهٔ عدم
تکرار برای آن هم برقرار است. متن تکراری رد می‌شود و برنده باید سؤال دیگری بفرستد.
تشخیص متن تکراری بر اساس متن یکسان پس از حذف فاصله‌های ابتدا و انتهاست.

برای جلوگیری از ثبت پاسخ زیر سؤال اشتباه، هر بازیکن ابتدا باید به سؤال باز قبلی‌اش
پاسخ بدهد و سپس سؤال جدید بگیرد. سؤال بی‌پاسخ از «ادامهٔ بازی‌ها» بازیابی می‌شود.
پس از پاسخ، طرف مقابل با «تأیید» یا «عدم تأیید» انجام حقیقت/جرأت را ارزیابی می‌کند.
تأیید دقیقاً یک امتیاز به مجموع `points_won` پاسخ‌دهنده اضافه می‌کند؛ عدم تأیید
امتیازی ندارد. امتیاز دست‌ها و برندهٔ مسابقه تغییر نمی‌کند. تصمیم و زمان آن در
`games.final_response_approved` و `games.final_reviewed_at` ذخیره می‌شوند و از طریق
`question_answers.game_id` به پاسخ مرتبط‌اند. هر پاسخ فقط یک بار قابل ارزیابی است؛
پاسخ‌های منتظر ارزیابی از «ادامهٔ بازی‌ها» و پس از راه‌اندازی مجدد در دسترس‌اند.
بازی‌های قدیمی با سؤال دستی همچنان قابل پاسخ‌دادن هستند؛ تاریخچهٔ قبلی آن‌ها به بانک
جدید نگاشت نمی‌شود. مهاجرت دیتابیس هنگام راه‌اندازی خودکار است و ریست لازم ندارد.

### اجرای تست‌ها

```bash
.venv/bin/pytest
```

تست‌ها قوانین بازی، مهاجرت پایگاه‌داده، بازیابی پس از restart، آمار، و ایمنی callbackهای تکراری/هم‌زمان را پوشش می‌دهند.


### اجرای دائمی با systemd

نمونهٔ [bazi_chi_bot.service](bazi_chi_bot.service) برای استقرار پروژه در مسیر
`/opt/bazi_chi_bot` و اجرا با کاربر و گروه `root` آماده است. آن را نصب و فعال کنید:

```bash
sudo install -m 0644 bazi_chi_bot.service /etc/systemd/system/bazi_chi_bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now bazi_chi_bot.service
```

مراحل تکرارپذیر هر به‌روزرسانی، پشتیبان‌گیری و بازگشت در
[راهنمای به‌روزرسانی سرور](DEPLOYMENT.md) آمده است.

وضعیت و لاگ‌ها:

```bash
sudo systemctl status bazi_chi_bot.service
sudo journalctl -u bazi_chi_bot.service -f
sudo journalctl -u bazi_chi_bot.service -n 100 --no-pager
```
